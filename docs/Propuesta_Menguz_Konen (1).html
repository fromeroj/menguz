1. Resumen Ejecutivo

Esta propuesta describe el desarrollo de un ecosistema digital completo para Menguz Vinos & Licores, compuesto por un sitio de venta B2C mobile-first, un portal mayorista B2B, un CRM inteligente con análisis predictivo, un módulo de logística con tracking, un motor de campañas de mercadotecnia, y el Club de Mixología como producto de suscripción recurrente.

La solución se despliega como un solo ejecutable en un servidor propio, sin dependencias de plataformas cloud propietarias, garantizando soberanía de datos, costos predecibles y simplicidad operativa.

4. Metodología de Trabajo

Konen.guru opera bajo el Método de los Siete Puentes: auditar, priorizar, diseñar, construir, lanzar, documentar y optimizar. Cada mes se divide en sprints de una semana con entregables concretos.

  • Semana 1: Planificación y diseño técnico del entregable del mes.
  • Semana 2–3: Desarrollo activo con revisiones intermedias.
  • Semana 4: Testing, ajustes, deploy a producción y documentación.

Al final de cada mes se realiza una revisión de entregable con el equipo de Menguz para validar funcionalidad y definir prioridades del mes siguiente.

ANEXO TÉCNICO
Arquitectura, Stack y Especificaciones de Implementación

A. Visión General de la Arquitectura

El sistema se construye como una única aplicación compilada en Go que incluye servidor HTTP, base de datos embebida, frontend estático y lógica de negocio. No requiere contenedores, orquestadores ni servicios cloud propietarios para operar.

Principio rector: Un solo binario ejecutable. Un solo directorio de datos. Un solo comando para deploy.

B. Stack Tecnológico Detallado

Capa Tecnología Versión / Justificación
Lenguaje Go 1.23+. Binario nativo, concurrencia con goroutines, compilación cruzada, zero-dependency runtime.
Framework HTTP Echo v4 Alto rendimiento, middleware extensible, validación de requests, manejo de errores estructurado.
DB Operativa Badger (dgraph.io/badger) Key-value LSM-tree embebido 100% Go. Escrituras concurrentes excelentes. Backup: copiar directorio.
DB Analítica SQLite (modernc.org/sqlite) Embebido, sin Cgo. SQL nativo para reportes, CRM queries, BI. Poblado por sync desde Badger.
Frontend HTMX + Tailwind CSS Zero JS framework. Interacciones vía AJAX que devuelven HTML parcial. Mobile-first. Embebido con //go:embed.
Autenticación JWT (golang-jwt/jwt) Tokens firmados con HS256. Refresh tokens rotativos almacenados en Badger.
Hashing bcrypt Contraseñas de usuarios con costo 12.
Sync SAE nakagami/firebirdsql Driver Go nativo para Firebird. Sin ODBC ni Cgo. Conexión directa al servidor SAE.
Chatbot IA OpenAI GPT-4o + SSE Server-Sent Events para streaming de respuestas. Contexto de catálogo via RAG.
WhatsApp WhatsApp Business API (Meta) Webhooks HTTP en Go. Catálogo, pedidos y notificaciones.
Pagos MercadoPago + Stripe SDKs oficiales en Go. Webhooks locales para confirmación de pago.
Facturación Finkok / SwSapiens API PAC autorizado por el SAT. Timbrado CFDI 4.0 vía HTTP desde Go.
Mapas / Rutas Google Maps API Geocodificación, distancias, optimización de rutas. Cliente HTTP en Go.
Deploy Binary + systemd scp del binario + restart del servicio. Backup con rsync del directorio de datos.

F. Frontend Mobile-First

F.1 Enfoque de diseño

  • Base: 375px (iPhone SE / dispositivos Android entry-level)
  • Breakpoints: sm:640px, md:768px, lg:1024px, xl:1280px
  • Touch targets: Mínimo 44×44px en todos los controles interactivos
  • Navegación móvil: Bottom navigation bar fija con 4 acciones principales
  • Carrito: Slide-up panel desde la parte inferior (no página aparte)
  • Checkout: Wizard de pasos con indicador de progreso
  • Imágenes: Lazy loading, formatos WebP con fallback JPEG

F.2 Tecnología: HTMX + Tailwind

HTMX permite interacciones dinámicas sin un framework JavaScript pesado. Cada acción (añadir al carrito, filtrar, aplicar cupón) es un request HTTP que el servidor responde con HTML parcial, que HTMX inserta en el DOM.

<!-- Ejemplo: añadir al carrito --> <button hx-post="/api/cart/add" hx-target="#cart-count" hx-swap="innerHTML" class="w-full bg-[#7B1F3A] text-white py-3 rounded-lg"> Añadir al carrito </button> <!-- El servidor responde con: --> <span id="cart-count">3</span>

//go:embed static/* var staticFS embed.FS // En main.go: echo.StaticFS("/static", echo.MustSubFS(staticFS, "static"))

K. Riesgos y Mitigaciones

RiesgoMitigación
Badger es single-nodeBackup diario automatizado. Si se necesita HA futura, migración a PostgreSQL es posible sin reescribir la lógica de negocio.
Consultas complejas en BadgerSQLite analítica como capa de lectura para CRM y BI. Badger para operación en vivo.
Equipo de Menguz no conoce GoDocumentación completa + capacitación en M12. Soporte mensual opcional con Konen.guru.
SAE bloquea conexión externaAgente de sync en el servidor local de Menguz que empuja datos al VPS vía HTTPS.
Crecimiento de datosBadger soporta terabytes. Compresión LZ4/Snappy activa. Garbage collection de valores obsoletos.
Nota final: Esta arquitectura prioriza la simplicidad operativa y la soberanía de datos. Cada decisión técnica está orientada a que Menguz posea, comprenda y opere su plataforma sin depender de infraestructuras propietarias complejas.
